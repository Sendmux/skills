Use the **saved, threaded mailbox draft workflow**, owned by `sendmux-mailbox-agent`. The agent reads the thread, saves a reply that a person can reopen and edit in Sendmux, and retains its stable draft ID and revision. Send through that saved draft only after the person approves the exact saved revision, including recipient, subject, body and attachments; later edits require approval of the new revision. Keep scheduling, cancellation and version checks with the same skill.

Draft preparation requires a Mailbox credential with `mailbox.read` and `mailbox.drafts.write`; sending additionally requires Mailbox `email.send` and explicit approval. Customer-connected outgoing accounts remain subject to mailbox send permission and sender policy. `sendmux-management` owns their connection and policy administration; it does not own the reply workflow.

Hand connection setup to `sendmux-cli` for REST OAuth or `sendmux-mcp-setup` for hosted MCP as needed, then validate access and select an authorised mailbox. No configured connection is established by this request. A self-registered read-only profile and its delegated Sending token alone cannot support editable Mailbox drafts. `sendmux-send-email` owns independent outbound sends and delegated Sending replies; the saved draft requirement routes this task to `sendmux-mailbox-agent`. Reconcile send retries using the same draft ID and approved revision; use targeted thread reads and delta sync rather than rescanning the inbox.
